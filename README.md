### CrowdPulse: A Mesh-Networked Edge-AI Early Warning System for Crowd Crush Prevention

**Abstract**

Mass public gatherings — religious festivals, election rallies, political campaigns — are a recurring feature of Indian public life, and a recurring source of preventable tragedy. Stampedes and crowd-crush events typically develop from localized precursors — a sudden surge in density, erratic or reversed movement at a chokepoint, rising acoustic panic — that are invisible to manual observation until the situation has already become dangerous. Existing crowd-safety infrastructure is largely reactive: CCTV reviewed after the fact, or simple sensor deployments that stream raw data to a cloud backend for analysis. This dependency is a critical design flaw, since venue networks are typically the first infrastructure to saturate or fail under the exact crowd load that makes monitoring most urgent.

CrowdPulse addresses this with a mesh of low-cost, battery-powered edge sensor nodes, each built around an **Arduino UNO Q**, deployed at fixed points across a gathering space. Each node independently senses three physical correlates of crowd risk: **movement and density**, via a Waveshare S3KM1110-based 24GHz mmWave radar sensor over UART, capturing presence, distance, and micro-motion without requiring line-of-sight or lighting; **environmental discomfort**, via a BMP280 (temperature and barometric pressure, I2C) and DHT22 (humidity, single-wire), both established contributors to crowd agitation and physiological stress; and **acoustic anomalies**, via a USB microphone connected through the board's USB-C host mode, distinguishing sudden panic-associated sound bursts from steady ambient crowd noise.

These signals are fused locally into a per-node stress score by the Uno Q's real-time STM32U585 co-processor, which handles deterministic, timestamp-synchronized sampling across the UART, I2C, and single-wire sensor interfaces — a design necessity, since stampede precursors are defined by *rate of change* across sensors rather than any single instantaneous reading, and sampling jitter would corrupt exactly the signal the system depends on.

Nodes exchange stress scores over a **LoRa mesh** (SX1278, SPI), chosen specifically for its independence from venue Wi-Fi and cellular infrastructure — the network layer most likely to be degraded at the moment monitoring matters most. On the Qualcomm QRB2210 Linux side, a quantized, lightweight anomaly-detection model runs inference across the fused multi-node data stream, identifying **cross-node correlation patterns**: a localized disturbance at one node — a movement surge, an acoustic spike — that predicts cascading risk before it is independently visible at neighboring nodes. This correlation layer, rather than any single sensor threshold, is the system's core technical contribution, and is what distinguishes CrowdPulse from existing single-node crowd counters or decibel-alarm systems documented elsewhere.

When correlated risk crosses a defined threshold, affected nodes trigger local alerts and flag the at-risk zone for event organizers — with the entire detection pipeline, from raw sensor sampling to anomaly inference to mesh alerting, computed at the edge and requiring no external connectivity.

The Uno Q's dual-processor architecture is the specific enabling factor for this design: the STM32U585 provides the deterministic multi-protocol sensor sampling (UART, I2C, single-wire) that real-time fusion requires, while the QRB2210 provides USB host support for live audio and sufficient compute for on-device model inference — capabilities that would otherwise require either splitting the system across two separate boards or offloading inference to a cloud service, undermining the project's core no-connectivity design goal.
